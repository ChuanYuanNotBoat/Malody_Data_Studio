日期：2026-10-18，Asia/Singapore。对应[修复计划](CRAWLER_REPAIR_PLAN.md)。

本次交付代码修复、回归用例、真实页面/API 小样本核对及人工重爬工具。**整体重爬没有启动，生产数据没有因本次实施而重写。** 先前已授权完成的本地凭据更新和 Not recommend 回填继续保留。

## 已实施

| 审计问题 | 实施结果 |
| --- | --- |
| 部分页面误覆盖 | 校验业务结构与对象 ID；记录字段出现状态；缺失字段保留原值，真实 0 可更新；新增未知字段为 NULL |
| 玩家资料/成就失败部分提交 | 资料、身份、排名使用可嵌套事务；先回滚业务修改，再记录失败；保存失败不能标记完成 |
| UID 与名字匹配 | UID 稳定匹配；当前名唯一索引及冲突检查；历史别名不能任取归属，不自动合并不同 UID；手动别名入口也不能绕过保护 |
| 部分集合清空旧记录 | 头衔、成就单独判断完整性；评论增量写入，完整代次才更新当前集合，旧事件保留为历史 |
| 元数据倒退 | 观测时间、源编辑时间和来源优先级分别判断；HTML 不降级覆盖已有 API 元数据；动态计数允许合法下降 |
| 玩家批量和范围入口不可用 | 补全批量方法；所有范围按固定块处理；修复脚本直接启动时的包路径；统一停止标记，无结束哨兵等待问题 |
| 登录/删除误判 | 移除 email 字段判登录；识别明确登录结构和最终 URL；确认 404 后才更新存在状态，保留内容 |
| 歌曲仅一张成功即完成 | 子谱面分别处理；SID 重试处理全部子项；部分失败不清除整歌失败状态 |
| 503 被记成永久空歌 | 返回完整性和错误原因；临时失败可重试；倒序发现模式不把网络错误当 404 或枚举上界 |
| 停止和末次重试丢进度 | 持久任务、租约回收和确认保护；重试队列停止不清空；末次重试结果再次落盘 |
| JSON 损坏静默重跑 | 临时文件加原子替换；损坏进度拒绝读取并保留原文件；进度保存失败明确抛错 |
| 新版来源重复第一页 | 持久化来源游标、待处理 CID 和筛选范围；达到限额后继续剩余对象；219 个 CID 分 22 轮限额测试无遗漏和重复 |
| 评论同秒/截断漏采 | 实测接口使用 `time < start`；边界重叠并按 TID 去重；重复游标、限额、错误均保持部分完成 |
| 来源精度与等级 0 | 页面/API 按共有精度比较，保留更精确原值；API 间真实精度变化保留；缺失等级不再写 0；EXP/MM/MMR 保存来源 |
| 搜索筛选被忽略 | 按实际前端使用 GET 查询参数；旧 POST 正文被服务端忽略、一直返回默认 Stable；当前模式/状态同时在详情保存前复核 |
| 相同名次造成漏人 | 实测模式 1 的 40 人只有 34 个不同名次，模式 2 为 39 个；按 UID 去重，保留不同 UID 的同名次记录，不自行改写源名次 |
| 已知玩家没有刷新状态 | 候选来自资料、身份、排名、MMR、状态和配置并集；分批选取并遵守 next_crawl_time；位图不再永久阻止刷新 |
| SID、名次、长度和标题误解析 | CID 17302 对应 SID 4448；修复第 4 名起头像容器抢先匹配；谱面与歌曲长度分开；去除 DOM 分隔符；未知 Mod 保留原代码 |
| 官方总数与投票事件混用 | `like/dislike` 为当前正负总数；不取事件数最大值；负向及未知 type=1 不计普通评论；当前接口排除历史非当前评论 |
| 缺少字段及追溯 | 保存 checksum、原文标题/艺术家、标签、独立歌曲时间；新增观测、完整性和有效变更记录；关联集合区分首次观察与真实获得日期 |

额外发现并修复：旧库有 **192,996** 条 `last_play_date='Never'`。它不是日期，开启 SQLite 日期转换时会导致读取异常。现在能安全读取旧值，并在确认源页面为 Never 时写入 NULL；本次没有批量改写这些历史行。

## 真实来源核对

本地登录态实测有效。对照了真实谱面 17302、歌曲 4448、玩家 100704、从未游玩的玩家 1149101、最近变动页，以及 CID 100591 的明确 404。新版 API 同时核对了 Stable、Alpha 谱面和玩家 MMR；结果仅写入内存临时库。另实测 0–9 模式的总榜首个响应均 `code=0`；旧站 GET 筛选返回的 CID 151903 实际页面为 Beta，与筛选一致。

| 样本 | 本次结果 |
| --- | --- |
| CID 17302 / SID 4448 | 对应关系正确，谱面原生长度 137 秒，歌曲长度 140 秒 |
| 官方投票 | 本次抽样 `like=3546`、`dislike=381`，独立于历史 talk 项数 |
| 歌曲 CID 集合 | 可解析 219 个，包含此前缺失的 161112、160725 |
| 页面成绩 | 40 条可见成绩全部解析到名次 |
| 玩家 | 完整资料及六个模式排名可解析；从未游玩玩家明确返回完整空排名集合 |
| 总榜补量 | 实测取得 75 人，第 75 名存在；`complete=false` 明确表示只取了约定限额，并未宣称全榜结束 |

**纠正此前审计假设：** `/page/all/player?from=50&mode=0` 返回的仍是前 50 名，不能证明 HTML 第二页可用。修复后的 HTML 入口只读取其可见榜单，再通过官方 `/ranking/global` 的 `hasMore/next` 补齐后续记录；每行分别保存页面或 API 来源。已在计划和本验收中更正。

真实响应和对照结果位于本地忽略目录 `logs/repair_baseline_20261018/live/`。纳入测试的 HTML 只保留业务节点，去掉登录表单、会话字段和非必要个人资料；不提交原始认证响应。

## 验证与数据保护

- 原有基线 237 项测试通过；本次新增 78 项，合计 **315 项通过**，包括 HTTP 路由、CLI、真实 DOM 回归、故障回滚、分页、219 子项恢复、双进程 MM 锁及人工发布保护。
- 临时库演练了增量迁移、重复执行、保存失败、执行租约接管、停止、人工启动、发布失败回滚和原库并发变更拒绝覆盖。
- `prepare/help/status/report` 不触发采集；`run` 和 `publish` 必须显式调用。没有设置自动调度，也没有在生产库创建本轮重爬任务。
- 恢复点包括一致性数据库备份、原工作区差异、源文件及进度文件备份，位于 `logs/repair_baseline_20261018/`。
- 本次实施结束时按表核对生产库与恢复点的行数和内容摘要，验证结果见同目录 `database_verification.json`。
- 统计/API 一致性门禁在一致性快照上通过：模式 0、3、5，限额 20/50，六组共 66 项比较均一致。使用实际 ASGI 路由验证，未启动生产服务。门禁另发现旧基准查询遗漏并列稳定者的热度排序，已与 API 统一并加入姓名末级排序和回归用例；没有改写统计数据。

## 人工后续与边界

操作见[人工重爬指南](MANUAL_RECRAWL.md)。只有人工核实 ID 上界、启动批次并完成之后，才能报告该批次的实际覆盖和数据校正结果。本次不把代码已修复等同于历史数据已经修复。

评论接口如果同秒记录超过单页容量而没有进一步游标，会保持未完成，不能证明不漏采。源站已经删除的历史、真实成就获得日期及未公开的游玩次数不能凭当前页面补造。未知 Mod 不猜名称。

发布会核对整个原库是否仍与基线一致；发现并发修改则拒绝覆盖，不提供自动三方合并。真实核对覆盖全部模式的首个总榜响应和三种状态的页面样本，没有声称穷举各模式榜单、每种状态或全部历史记录。
