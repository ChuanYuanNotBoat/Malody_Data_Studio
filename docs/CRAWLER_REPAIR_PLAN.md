## 0. 建立恢复点与测试基线

- 保存当前工作区差异，保留已有未提交修改；只把本次修复涉及的改动纳入各阶段交付。
- 在数据库迁移及回填前使用 SQLite 一致性备份；进度文件单独备份。备份不通过直接复制一个仍在写入的数据库文件完成。
- 保存计数基线：谱面/歌曲/玩家/评论数量，外键引用、重复 UID、字段未知数、队列覆盖数、失败任务和最后成功时间。
- 将审计中保存的真实页面/API 内容整理为脱敏测试样本。原先断言“缺陷仍可复现”的脚本仅作证据，修复验收使用断言正确行为的回归测试。
- 在项目隔离环境中补齐路由测试所需的 `httpx2`，恢复相关 HTTP 测试；先确认基线失败，避免把环境故障混为修复回归。

## 1. 防止误覆盖、部分提交和身份错配

主要文件：`crawlers/stb.py`、`crawlers/player_profile.py`、`crawlers/rankings.py`。

### 抓取与保存契约

共享结果至少包含：请求对象 ID、实际对象 ID、来源、观测时间、源编辑时间（如可获得）、实际出现的字段、列表是否完整、下一页游标及失败原因。

字段更新规则：

| 情况 | 写入规则 |
| --- | --- |
| 页面无此字段、解析失败、字段未公开 | 保留已有值；首次采集为未知 |
| 来源明确返回 0 | 允许写入真实 0 |
| 来源明确返回空值或空集合 | 仅在字段/集合完整且语义确定时清空 |
| 只有部分列表或部分页面 | 合并明确采集到的项目，保留未看到的已有项目；不宣称全量完成 |
| 请求 ID 与正文 CID/SID/UID 冲突 | 拒绝写入并记录异常 |
| 旧元数据或较低权威来源 | 按字段来源与版本规则处理，不直接覆盖较新、较可靠的数据 |

将整行 `INSERT OR REPLACE` 改成受字段出现状态约束的更新。头衔、成就和评论分别记录集合完整性；完整性不足时不执行全量删除。保留已有成就/头衔时间，不在每次刷新时重建为当前时间。

### 事务与身份

- 单个业务保存由调用方明确持有事务；内部身份解析不随意提交外层事务。
- 业务失败先完整回滚，再独立写失败状态。只有必要保存成功，才能写完成状态；资料与排名的部分完成分别记录。
- UID 为稳定身份依据，当前玩家名按源站规则唯一；当前名与历史别名分别维护。改名更新同一 UID 的当前名，并保留其已观察到的旧名。
- 同一当前名对应不同非空 UID 时，作为源规则冲突、陈旧记录或解析异常核对，不能覆盖 UID 或自动合并历史。无 UID 时仅允许用已验证的唯一当前名关联，不能任取历史别名的第一条。
- 检查旧库重复 UID 及当前名冲突并核实陈旧名称后，再增加相应唯一性保护；名称大小写、空白等比较方式跟随源规则，不擅自归一化合并。
- 源站是否允许改名后旧名被其他 UID 重新使用尚未核实；保留防护测试，但不将这种情况描述为已证实的源站行为，也不将其等同同时重名。

验收：真实完整样本后接缺字段样本，原字段和关联集合保留；成就插入失败时主记录及关联修改全部回滚；保存失败不标 done；改名仍归属原 UID，当前名冲突不能改写另一 UID；重复执行同一更新不增加重复业务记录。

## 2. 修复采集入口、登录/删除识别及 MM 锁

主要文件：`crawlers/player_profile.py`、`crawlers/stb.py`、`crawlers/rankings.py`。

- 实现 `crawl_players_batch`，统一单 UID、列表、文件、数据库和排行榜入口的执行与结果统计。
- 统一停止信号来源；每次从队列取出的任务和结束哨兵均完成计数；生产者异常、消费者异常和停止流程均能退出。
- 登录识别采用最终 URL、明确登录主结构、必要业务结构综合判断，移除仅凭 `name="email"` 判整页登录的规则。
- 连接检测分别报告网络可达、登录有效、内容有效，避免 HTTP 200 登录页被描述为采集成功。
- 区分谱面明确 404、登录重定向、访问拒绝和站点错误。删除只改变存在状态并保留本地历史。
- MM 锁核实所属进程及启动身份，避免 PID 重用或简单按文件年龄判断。确认遗留锁后恢复，活跃任务仍保持互斥。

真实验收样本：已登录 `/page/latest` 正常使用；过期凭据登录重定向明确失败；CID 100591 的 `Page Not Found` 能识别；正常谱面不被误删；同 UID 批处理和范围处理能结束；MM 遗留锁可恢复且双实例不能并发运行。

## 3. 修复任务状态、重复采集、分页与断点恢复

主要文件：`crawlers/stb.py`、`crawlers/player_profile.py`、数据库迁移及任务状态辅助模块。

- 分开歌曲发现、CID 列表获取、单谱面详情、评论列表和玩家各数据部分的完成状态。一张 CID 成功不代表整首 SID 完成。
- 引入持久任务记录，至少保存对象及筛选范围、任务状态、尝试次数、下次重试时间、执行租约和继续游标。相同范围内的待处理任务去重，已成功任务按刷新周期再次调度。
- 新版来源达到每轮限额时保存剩余 CID 与游标；下一轮继续，避免反复只处理第一页。筛选条件变化时不混用旧游标和完成标记。
- 超时、503、登录失败与无法解析均进入可重试状态；只有确认成功且确实为空的列表才记录为空，并允许之后重新检查。
- SID 重试必须处理全部未完成 CID；中途成功不清除整首歌的剩余任务。
- 停止时归还未处理任务；最终重试结束后再次持久化状态。遗留 JSON 进度采用临时文件加原子替换；损坏时使用可验证恢复点，不静默从默认起点重跑。
- 评论分页使用稳定游标或有重叠的去重策略；遇到同秒时间边界、重复页或无法证明翻页完成时，保持部分完成状态。
- 统计区分唯一对象、实际请求、保存成功、跳过、部分成功和失败；跳过不计为新完成采集。

验收：219 个 CID 在多轮限额下最终全部到达；成功一张后其他 CID 仍可被调度；503 不进入永久空列表；停止/重启及“写库后、确认前”崩溃不丢任务、不新增重复业务记录；末次重试成功不会在下次恢复时复活；同秒分页不漏项目。

## 4. 修复解析与统计口径

主要文件：`routers/page_parser.py`、`crawlers/stb.py`、`crawlers/rankings.py`、`crawlers/chart_votes.py`、`core/services/chart_service.py`。

- SID 从歌曲元数据/链接提取，CID 独立校验；修复从第 4 名开始的 `i.ranknum` 名次解析。
- 歌曲长度使用歌曲元数据，谱面长度使用谱面元数据。歌曲更新时间不再使用任一关联谱面的时间代替。
- 标题从正确 DOM 正文提取；保留原文与其他显示名，避免前导分隔符和来源切换造成覆盖。
- Mod 按独立 CSS 类匹配，只有有可信依据的名称才映射；未知值保留原始代码，不输出猜测名称。
- 当前正/负投票总数分别采用官方 `like/dislike`。保留已补齐的 Not recommend 方向标记；事件数量单独查询，不能对官方总数和事件数取最大值。
- 评论数只有完整成功抓取时才可作为完整汇总；部分数据只报告已采集数量及完整性。
- 不对投票、热度等动态值统一执行“只增不减”；合法取消投票应正常反映。元数据版本判断与动态计数观测时间分别处理。
- EXP、MM、MMR 保存来源；来源间准确率精度统一比较，保留可靠原值，不能因 HTML 舍入制造变化。等级未提供时视为未知，不能写 0 覆盖已知等级。
- 所有支持的来源统一应用模式/状态筛选。HTML 总榜记录可见范围，后续通过官方 API 明确分页，支持数量限制并输出实际完整性。

验收样本：CID 17302 → SID 4448；40 条页面成绩均有名次；该谱面长度 137 秒、歌曲长度 140 秒；官方不推荐数与记录一致；API/HTML 切换不产生等级 74↔0；第 51 名之后的玩家能够被采集；明确的数值下降正常更新。

## 5. 更新范围、缺失字段与兼容迁移

主要文件：`crawlers/player_profile.py`、`crawlers/stb.py`、`crawlers/rankings.py`、`core/models.py`、相关 API/CLI 查询及迁移脚本。

- 待更新 UID 来自资料表、身份表、已有状态表及显式配置的并集，按 UID 去重；分批读取，不把百万 UID 一次性装入内存或立即发出请求。
- 任务选取使用 `next_crawl_time` 与最近成功时间，失败退避真实生效。全局完成位图作为历史发现记录，不能无限期阻止过期资料刷新。
- 补齐 `checksum`、原文标题/艺术家、可识别标签、独立歌曲更新时间，以及来源和完整性元数据。没有可信源的字段保持未知。
- 对现有表做可重复执行的增量迁移；既有 API 字段和含义保持兼容，新增字段先可空；旧数据库可读，迁移失败明确报错。
- “首次观察到成就的时间”与“实际获得时间”分别定义。谱面/歌曲/资料保存有效变更记录，或以明确范围提供快照；无法回溯的历史不伪造。
- 原始响应不长期无界保存：保留用于诊断的必要样本及校验信息，并定义限量保留策略。

验收：已知 UID 均可进入刷新候选集合；尚未到重试时间的任务不入选；新旧数据库查询均通过；缺字段不会默认伪装成已知 0；既有 Not recommend 计数、标记和备份保留。

## 6. 完整修复验收

- 阶段 1–5 的未修复项逐项关闭，回归测试验证正确结果；同时覆盖当前名唯一、同一 UID 改名及异常名称冲突。
- 在临时库完成增量迁移、部分写入失败回滚、中途停止、崩溃恢复及重复运行演练。
- 使用实际 Malody 页面/API 做有限小样本对照，验证计数口径、所有模式与状态、404、登录失效、完整分页和新增字段。
- 此时只做验收样本，不启动整体采集。验收通过后建立阶段 7 的独立重爬批次。

## 7. 整体重爬与历史数据校正

这是完整修复后的必要阶段。采用固定大小、可继续的批次，遵循现有限速和失败退避，覆盖范围不只限于此前发现的异常记录。

### 范围与执行方式

1. 开始前核实并记录本轮 UID/SID/CID 枚举范围、可用数据源及分页边界。覆盖所有已知 ID，并通过源站清单和可确认的 ID 范围发现未入库对象；无法验证的边界明确记录，不能宣称覆盖未知范围。
2. 玩家部分重新采集范围内资料、当前名、头衔、成就，以及各模式可获取的 EXP/MM/MMR 数据；排行榜遍历本轮约定的完整可枚举范围，不沿用日常 Top N 限额冒充全量。
3. 歌曲和谱面部分覆盖全部支持模式及 Alpha/Beta/Stable，重新获取歌曲元数据、CID 集合、谱面详情、正/负投票总数和完整可获取的评论/投票事件；已有对象也重新核验存在状态。
4. 使用新的重爬批次 ID 和持久任务状态。旧完成位图、`processed_songs`、历史空列表和旧失败标记不直接跳过本轮任务；本轮已确认完成的任务可在恢复时去重。
5. 抓取结果先写本轮隔离区，保留现有库及历史数据；完成验收后按 UID/SID/CID 合并当前数据，维持身份关联，不直接清空旧库重建。当前页面无法恢复的旧历史仍保留，不用当前值填造过去。
6. 每批保存继续位置、失败类型、重试时间、唯一对象数和完整性；token 过期、风控、网络错误及部分分页都不计为完成或真实空数据。
7. 收尾核对本轮起止边界与采集中产生的变化，补齐可确认的新对象及未完成分页；输出覆盖、差异、重试残留和不可访问对象清单。数据变化较大时允许必要的收尾追赶，但不混淆本轮基准范围。

### 已知异常在整体重爬中的处理

| 历史对象 | 校正方法 | 不采用的推断 |
| --- | --- | --- |
| SID 4448 的缺失谱面 | 重新获取当前 CID 集合，核对 CID 161112、160725 后补采 | 不直接把早前 219 作为永久固定总数 |
| CID 100591 的存在状态 | 再次确认明确删除后更新存在状态，保留本地内容 | 不因列表缺席或访问被拒而认定删除 |
| 错误投票/评论汇总 | 从官方总数与完整评论结果分别更新，保留已纠正方向 | 不从总推荐数直接减去历史负向事件数 |
| 被误记为空/失败/完成的 SID、UID | 导入为待核对或到期复查任务，按批验证 | 不把 13,124 个空 SID 或全部位图项直接判为错误 |
| 未进入状态表的资料 | 全部纳入本轮重爬队列，分批执行并保留进度 | 不因没有旧状态行而跳过，也不一次性集中发请求 |
| 标题、长度、更新时间和缺失字段 | 按权威字段重新采集，并保留旧值和改动依据 | 不批量裁掉所有以连字符开头的合法歌名 |
| 当前名唯一性冲突和已丢失历史 | 按 UID 与实时当前名核对，利用备份及明确证据恢复 | 不把当前重名当正常情况，也不按历史别名合并不同 UID |
| MM/MMR 停更 | 修复锁和采集流程后恢复当前采样 | 不用当前值填造过去缺失日期的快照 |

每批保存：任务范围、源观测时间、旧值/新值、修复依据、失败项及继续位置。回填写入检查原记录是否已被其他任务更新；冲突项重新抓取，避免用旧修复计划覆盖并发的新数据。
